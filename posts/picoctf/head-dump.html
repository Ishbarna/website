head-dump: When API Docs Say Too Much

May 6, 20253 min read50 points

In picoCTF 2025's 50-point head-dump challenge, the goal is to find a hidden flag inside a server memory dump. The challenge tests a practical skill: reading API documentation, identifying useful endpoints, and searching messy output for a small secret.

Challenge overview

The starting point is a basic blog application. Exploring its pages reveals an API Documentation link, which opens /api-docs and a Swagger UI. Swagger lists the routes exposed by the application and lets you inspect or execute them from the browser.

Find the diagnostic endpoint

The useful route appears under the Diagnosing section. Searching the documentation for terms such as diagnosing, dump, or heap leads to /heapdump. Its description hints that it generates a memory dump, matching the challenge name.

Execute the endpoint from Swagger and download the returned file. The dump is too large to inspect manually, so open it in a text editor or search it from the command line. Searching for pico or the expected flag prefix quickly surfaces the flag inside the raw output.

Lessons from the challenge

The solution is simple once the right route is found: explore the application, read its API documentation, identify the heap dump endpoint, download the file, and search it. In a real application, diagnostic endpoints that expose memory, configuration, or logs should be removed from production or protected by strong authentication.
